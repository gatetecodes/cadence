# Cadence

A calm, ad-free intermittent fasting tracker for iOS and Android. One tap to start, a live timer on the lock screen for the whole fast, and nothing else in the way.

Requirements live in the BRD: https://claude.ai/artifact/DWwpmHCn9f94bGwt25VJWy

## Stack

Expo SDK 58 (React Native 0.88, New Architecture) · TypeScript · Expo Router · Zustand · expo-sqlite + Drizzle · react-native-svg · expo-notifications · expo-widgets (iOS Live Activity) · a local Kotlin module for the Android live notification.

No backend. All data stays on the device.

## Getting started

```bash
npm install                 # .npmrc sets legacy-peer-deps
npm test                    # fast engine unit tests
npm run typecheck

npx expo run:ios            # dev build on simulator / device (needs Xcode)
npx expo run:android        # dev build on emulator / device (needs Android Studio)
```

Expo Go will not work: the app uses native code (Live Activity, the Android live notification). Use a dev build (`npx expo run:*`, or `npx eas-cli build --profile development`).

`ios/` and `android/` are generated by `npx expo prebuild` and are git-ignored. Configure native behaviour in `app.json` and in `modules/`, never by editing those folders.

## How the live timer works

Nothing counts seconds in the background. The app hands the start time to the OS and the OS draws the timer.

- **Android:** `LiveFastNotifier` posts an ongoing notification with a chronometer counting up from the start. On Android 16+ it asks to be promoted to a Live Update with a progress bar split into zone segments; its status bar chip shows the icon only (no ticking time). An inexact alarm re-renders it every 15 minutes until the goal and at each zone boundary; a boot receiver restores it after a restart. "End fast" opens `cadence://end-fast`.
- **iOS:** a Live Activity (lock screen + Dynamic Island) uses SwiftUI timer text and a timer progress view, so it ticks with zero updates. iOS ends Live Activities after 8 hours, so the app restarts it whenever it comes to the foreground; scheduled notifications cover the rest of the fast.
- **Between fasts:** the same surfaces count down the eating window (24h minus the last fast's goal), with a "Start fast" action that opens `cadence://start-fast`. Android removes the notification when the window closes; on iOS the activity goes stale at that moment (showing "Time to fast") and is ended the next time the app opens. Settings → "Eating window on lock screen" turns this off.
- **Both:** zone changes, 30 minutes to goal, goal reached (time-sensitive on iOS) and eating-window alerts are planned by `engine/notificationPlan.ts` and rebuilt from the database after every change.
